# BotHub

群房间现为完整的办公空间，包含木质办公桌、电脑、键盘、办公椅、书架、
白板和绿植。公共区包含带微波炉的茶水吧、斯诺克球桌、沙发休息区，以及
跑步机、哑铃和瑜伽垫组成的健身角；成员工位保留在独立前区。点击桌椅或成员
可查看工作，空闲角色可以使用公共设施。模型和表面纹理全部本地生成，无需下载素材。

工位显示器可以通过只读截图显示对应 Bot 正在运行的私有桌面。本功能需要
**同时更新 DS Bot 和 BotHub**：DS Bot 必须提供 `passivePreview` 能力，
保证后台屏幕不会推迟桌面自动休眠。最多四个可见 Bot 约每秒刷新一次，
截图最多两路并发；同一 Bot 在多个群房间共用画面。打开 BotHub 不会启动
或接管桌面。普通 Agent 继续显示待机画面。

浏览器支持 Web Locks 时，同一存储分区中的多个窗口轮流采集同一个 Bot，
通常合计每秒一张。各窗口独立经过认证获取画面，不广播或持久化图片。
窗口越多，每个窗口刷新越慢；关闭或隐藏预览会取消等待。不支持锁时继续
使用已有的单视图限制。

未启动或未配置的桌面显示原创待机动画。正常档在进入 3D 时短暂播放，
活泼档循环播放，安静档和系统减少动态效果使用静态画面。桌面忙碌时，
短暂保留最后画面并标记等待，连续五秒未获得新图即清除。页面隐藏、断线、
切换房间或退出 3D 时取消预览并释放不再使用的画面。屏幕保持桌面原始比例。
预览传输完整 PNG，在本地缩小为 512 × 276 贴图；尚非视频流，也不转发
鼠标键盘操作。

点击 Bot 工位的电脑屏幕，或在 2D / 3D 的成员详情选择“查看桌面”，可打开放大
只读窗口。“适应窗口”保持画面比例，“原始大小”按原像素显示并允许滚动。
打开期间仅采集当前 Bot；按 Escape 关闭后返回入口焦点并保留场景视角。
断线、页面隐藏或权限变化会清除画面；切换工作区或删除 Bot 会关闭窗口。
放大窗口仍使用定期截图，更流畅的视频流和真实容器端到端验收尚未完成。

场景跟随宿主的深浅主题。在场景内的“画质”选择器中，可选“节能”、
“均衡”（默认）或“精细”。节能关闭阴影，其他档位限制阴影分辨率和像素比。
当前浏览器会记住选择；切换画质保留镜头与成员选择。标签密集时优先显示
房间、选中成员和工作状态；用 Tab 可显示隐藏标签并继续键盘导航，2D 始终
保留完整列表。

选择 **动作 → 活泼**，工作中的角色会快速敲键盘、冒汗并擦汗；空闲时可以
起身接水、喝咖啡、伸展、举哑铃、趴桌小睡并飘出 Zzz，或练习斯诺克。
群办公室配有饮水机，咖啡和斯诺克使用公共区设施。角色沿过道移动，
共享设施轮流使用；新任务会中断离席动作并让角色沿原路回工位。
标签、点击目标和近景镜头始终跟随同一成员。
走路时空闲手臂与对侧腿配合摆动。去饮水机接水或去咖啡机泡咖啡时，
往返都拿着杯子，走路时杯子保持直立；只有到达设备后才显示注水。

**正常**（默认）只在工作状态变化后展示最多 5 秒敲键盘；**安静**、
系统减少动态效果或实时连接中断时关闭角色动作，页面隐藏时暂停。
动作档位只保存在当前浏览器。空闲动作仅为场景表现，以真实状态标签为准：
睡觉不会暂停 Bot，动作不会调用模型；Zzz 不播放声音，斯诺克也不是可操作游戏。
“尚未观测”不会被当作空闲。角色动作本身在已有兼容桥接时只需更新 BotHub；
私有桌面预览需要配套更新 DS Bot。

3D 视图现按群组织：一个群对应一个房间。同一 Bot 加入多个群时，在每个房间
都有席位，但团队人数只计一次。席位只显示本群中的活动；私聊和普通 Agent
位于公共区，子 Agent 跟随其实际根会话归属。点击房间名进入房间，再选择成员，
即可打开对应群聊。

点击 3D 席位会进入对应房间并拉近查看成员。可通过位置导航或 Esc，按
“成员 → 房间 → 总览”返回。用 Tab 聚焦场景后，方向键旋转、+/− 缩放、
Home 重置当前视角；搜索框和选择器保留正常按键行为。实时刷新保留镜头角度
和缩放。切换 2D 保留群内选择；2D 总览中的聚合选择切回 3D 时会清除。

总览最多渲染 24 个房间、50 个席位。可通过群筛选查看总览未显示的房间，或
切换 2D 查看全部匹配成员。空群也保留房间。在首次执行前打开群聊，需要
包含 `groupNavigation` 支持的配套 DS Bot 工作区版本。

## 实时更新与恢复

同一浏览器存储分区和监控路径只保留一条经过宿主认证的 BotHub 数据流，
其他窗口独立轮询快照，为桌面预览和操作保留连接。数据流先接收完整基线，
再更新变化的成员、会话、运行和群。断线后从最后已应用的版本恢复；
宿主重启或补发缓存过期时自动读取新基线。

断线时保留最后已知场景，并禁用操作。页面隐藏时关闭数据流，重新可见时恢复。
流不可用、被其他窗口使用或浏览器不支持 Web Locks 时，显示定期更新提示，
并自动探测是否可以开启数据流。
认证失败会清空视图；重新登录后点击 **刷新**，或由 DSH 新的已认证连接
通知自动触发基线重查。

数据流包含当前观测状态和有界的最近结束记录，不是完整运行历史。配套桥接能保留
采样之间完成的短回合；旧桥接仍可能漏掉这类活动。
流中不包含消息正文或工具输出。已有兼容 DS Bot 安装时，只需更新 BotHub。

## 执行会话

每条运行都有 **查看执行会话** 按钮。同一 Bot 同时在私聊和多个群工作时，
会打开所选运行对应的会话。群 Bot 请在群详情中找到该成员，停止其在本群的工作；
其他本地运行请在原会话确认当前工作后，再使用停止按钮。打开会话本身不会停止工作。

当前固定 DSH 版本的公开 API 无法原子校验并只取消指定 Run，因此 BotHub
保留原生停止入口。断线时禁用运行链接；只读主机允许查看，实际操作仍由持有团队的
主机处理。已有兼容安装时，这一改动只需更新 BotHub。

## 快捷消息

配套 DS Bot 提供 `messaging: 1` 能力后，Bot 详情会提供最多 4000 字符的
纯文本输入框。公共区和 2D 总览中的选择发送到该 Bot 当前私聊；群房间中
发送到**本群群聊**，沿用群聊分发与 @ 提及规则。输入框上方会明确标注目标。
普通 Agent 和子 Agent 继续在原会话中交互。

“已受理”只表示消息被接收，不表示 Bot 已完成任务。超时后显示受理状态未知，
请“查询回执”或检查原会话；查询不会重发消息。“写新消息”清除当前草稿和
回执显示，不会取消先前提交。

切换成员／房间时，草稿保留在插件内存。刷新只从会话存储恢复命令标识和目标，
以便继续查回执，不恢复消息正文。只读主机禁止发送。旧桥接仍能监控和跳转，
快捷消息会明确禁用。

配套桥接在派发前保存命令标识、作用域、目标、正文摘要和受理状态，
回执台账不保存正文。预览版最多保留 2048 条回执，到限后拒绝新的快捷消息，
原会话仍可使用。不要通过删除台账重试受理状态未知的请求。
恢复只查询有界的宿主证据；找不到证据时保持未知。

## MVP 范围

- 搜索团队、按群聊和状态筛选、统计运行数与待处理成员数。
- 同一 Bot 的私聊和群执行分别展示，身份不重复。
- 支持 3D 选中、旋转与缩放，也提供等价的 2D 导航。
- 被动监控；打开 BotHub 不创建 Bot，也不启动模型。
- 尚未收到实时回合的会话显示“尚未观测”，不会假定为空闲。
- 断线保留最后快照并禁用会话跳转；认证失效清空数据。
- 监控只传标识、名称、角色、工具名和状态分类，不传聊天正文、指令、
  文件路径、工具参数或密钥。

已登记的普通 DSH Agent 和本地子 Agent 显示驻留 Agent 的真实运行/空闲状态，
未驻留会话保持“尚未观测”。父子关系来自 DSH 的明确目录，可在详情中选择父成员
或子 Agent，并打开原生子会话。外部子 Agent 无法在本地打开。
每次快照最多读取 64 个目录、发现 64 个子节点、深入 4 层、用时 2 秒，覆盖不完整
时显示提示。监控不会加载或唤醒 Agent。

现已通过公开 DSH 事件和投影观测工具活动、回合起点、等待审批及待回答问题，
并行工具分别结算。timed 问题超时后仍可回答，Agent 也可以继续工作；此时成员
保持待处理提示，但不会把执行误报为暂停。问题和审批正文仍只在原生会话展示。

投影不可用时明确提示细节缺失。插件加载前已经阻塞的旧版提问无法补获实时等待
事件，只能看到仍在执行的提问工具。未驻留会话、完整历史、场景编辑
和直接停止／审批控制继续后置。

## 要求与安装

本预览版以仓库的 DSH `0.2.1-rc.4` 为基线，需要安装**包含
`src/host/monitor.js` 的 DS Bot 工作区版本**。旧的已发布 DS Bot 会显示
桥接不可用提示。快捷消息还需要配套的 `src/host/monitor-commands.js`，
本切片应**同时更新两个插件**。插件不修改 DSH。

1. 使用 Node.js 22.19+，在本目录构建：

   ```sh
   npm ci
   npm run build
   npm test
   npm run lint
   npm run check
   ```

2. 在 DSH 插件管理中安装本地包目录，与兼容的 DS Bot bundle 一同启用。
3. 从 DS Bot 侧栏底部、账户按钮旁的立方体按钮打开 **BotHub**。
   普通 DSH 侧栏也提供 BotHub 面板入口。
   设备无法建立 WebGL 渲染器时，使用 **2D**。
4. 点击成员，使用“快捷消息”或“打开会话”。群房间内的快捷消息发送到该群主会话；
   完整回复、审批和成员控制由 DS Bot 原生会话处理。

这是当前主机中已登录用户的 DS Bot 团队视图，不是多租户监控 API、
模型可调用工具或外部 CLI 收集器。它复用 DSH 认证连接服务和同源请求，
无需新增服务器或端口。

禁用 BotHub 会移除通道、界面与渲染器，不会停止团队。面板可见时使用事件流并每 5 秒核对，降级时每 2.5 秒
获取快照；页面隐藏时不绘图，也不发起新的轮询。3D 最多显示 50 个上下文
席位，2D 可查看全部匹配成员。不使用外部素材或 CDN。

## 隔离开发测试台

使用当前操作系统原生的 Node 和 pnpm，不要让 Linux DSH 进程使用 Windows
创建的包链接。辅助脚本通过公开的已安装 `dsh` CLI 和仓库模拟模型启动：

```sh
# 在仓库根目录执行，选择未占用的端口。
CONTEXT_WINDOW=100000 CHECK_RATIO=0.45 \
  sh dsh-bothub/dev/bench.sh bothub-smoke 3196 8896 start

# 现有 host 回归冒烟：
node ds-bot/dev/smoke.mjs bothub-smoke 3196

# 结束时停止测试台进程。
sh dsh-bothub/dev/bench.sh bothub-smoke 3196 8896 stop
```

测试台仅写入 `.dsh-test-bothub-smoke/`。可用 `DSH_CLI` 指定其他已安装的
公开 CLI，不使用用户真实 DSH profile。

在 WSL 中，测试数据目录必须支持仅所有者可读的文件权限。若 Windows 挂载盘
将所有文件报告为 `777`，请在 Linux 文件系统建立新的测试目录，并在**首次
启动前**将 `.dsh-test-bothub-smoke` 符号链接到该目录。不要放宽 DSH 的凭证
权限检查。

在该 mock 测试台中，从团队菜单新增 **DSH Agent**，在其原生会话发送
`BotHub work 10`，再打开 BotHub 观察“执行中 → 空闲”。随后发送
`BotHub delegate 20`，DSH 会真实启动名为 **BotHub review task** 的本地子 Agent。
可在 BotHub 中选择它、查看父成员并打开原生子会话。这些固定命令仅供 mock
测试使用，没有为正式模型增加专用命令。

alpha.3 可发送 `BotHub tool 10` 观察真实的无害 shell 工具；发送 `阻塞提问`，
在 BotHub 确认等待提示后回原生会话回答；再发送 `BotHub approve`，确认等待审批
提示后回原生会话拒绝请求，检查待处理状态清除。

## 开发约定

在本目录运行 `node scripts/build-scene-benchmark.mjs`，然后在本地测试端口
提供生成的 `../.playwright-mcp/bothub-scene-benchmark/`，即可运行合成的
20／50 席位基准。浏览器视口宽 1920px、设备像素比 1 时，在控制台依次执行
`await runBenchmark({ count: 20 })`、`await runBenchmark({ count: 50 })`。
基准使用实际渲染器、原创模型和标签布局，不需要宿主或模型；输出 CPU 回调
耗时、帧间隔、WebGL 绘制调用和资源循环。CPU 耗时不是 GPU 完成时间。
这与真实宿主集成验证、录制台架分开运行。

- `client.js` 从 `src/client/` 生成，不手工修改。
- host 消费由 DS Bot 提供的 version-2 `botMonitor` 服务。
- DS Bot 在自有侧栏底部声明可叠加的 `bot.sidebar.action` 列表槽位，
  配套插件可通过 `slots.inject` 注册入口。
- GET `api/bothub` 返回最小快照。POST 支持
  `{ action: "resolve", entityId, sessionId?, groupId? }` 导航、
  `{ action: "send", commandId, workspaceId, entityId, groupId, text }` 显式发送、
  `{ action: "receipt", commandId }` 查询受理。命令需要 JSON 和宿主用户认证；
  私聊使用 groupId: null。
- GET `api/bothub/events` 推送带版本的快照/增量；`Last-Event-ID` 只用于
  有界补发，不能选择工作区。共享缓存最多 128 条增量或 1 MiB；每个读者
  队列上限 1 MiB，连接 60 秒后重建并由宿主重新认证，最多 16 个并发读者。
  通知合并窗口 150 ms，5 秒定期核对，15 秒心跳。轮询降级成功后每 2.5 秒
  检查，12 次成功后探测数据流；失败按带抖动的退避重试，上限 30 秒。
  客户端 Web Locks 将每个存储分区/路径限制为一个流读者；其他视图立即轮询，
  不把正常的窗口协调显示为连接失败。
- 导航返回 `{ target }`：根会话 ID 或经后端确认的原生地址
  `{ parentSessionId, childSessionId, mode }`。
- 群成员会话映射回群聊。Bot 默认会话在点击时解析到当前段。
- 状态、尺寸、镜头变化和启用的角色动作会触发绘图；画质档限制动作帧率为
  12／24／30 fps。卸载释放几何体、材质、监听器和
  WebGL context。

## 候选版安装、升级和回滚

`0.1.0-rc.4` 对应 DSH `0.2.1-rc.4`、Cordis `4.0.5`。通过宿主插件管理器的
本地 bundle 安装，先安装**同一候选目录**内的配套 DS Bot 包，再安装 BotHub 包。
配套 DS Bot 包版本仍为 `0.2.16`，仅凭版本号不能确定桥接兼容性；请核对候选的
SHA-256 清单。两包更新后重启宿主，每个 bundle 只启用一份。旧版公开 DS Bot 不够。

如果已安装 rc.3 的成对候选包，本次步态和持杯修复只需更新 BotHub；
配套 DS Bot 安装包没有变化。

首次检查：打开 BotHub，确认“已连接”，在 2D 选择 Bot，发送短消息，确认“已受理”，
打开原会话查看回复；切到 3D，进入群房间，核对消息目标。未启动的桌面应显示待机，
不能因为打开 BotHub 就启动容器。

插件管理器禁用 BotHub 后重启，其面板和监控通道移除，DS Bot 团队继续运行。
回滚时禁用 BotHub，重新安装之前保留的 BotHub bundle 并重启；保留兼容的 DS Bot
桥接，旧 BotHub 会忽略新增的结束记录字段。不要删除团队、会话数据或消息回执账本。
再次安装候选包即可恢复升级；BotHub 无需数据迁移。

“最近结束的运行”默认折叠，点击标题展开。新增记录通过以下方式提供：配套桥接通过公开 Session projection，每个可观测会话最多
保留 16 条结束记录，能显示两次采样之间结束的短回合；详情汇总当前范围内最近的
最多 16 条，区分完成、停止、失败和结果未知。记录不计入活动数，不含正文或错误
详情。非驻留会话不加载也不推断结果；成员删除、会话换段后旧记录退出当前视图。
旧桥接仍可能漏掉采样之间的短回合，这不是完整历史。

当前验证基线为 Linux/WSL DSH Web 宿主和 Windows Chrome 客户端；Electron、Safari、
macOS 和真实容器私有桌面仍需单独验证。精确运行取消、内嵌审批、视频流、完整历史、
空间编辑和外部 CLI 监控不在此 MVP 的能力承诺中。
