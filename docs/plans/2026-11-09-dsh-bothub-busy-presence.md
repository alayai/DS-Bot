# BotHub：私聊工作不能在群房间显示空闲

- 日期：2026-11-09。
- 来源：用户截图中秘书正在私聊阅读网页，BotHub 总计有一个执行，但群席位显示空闲并做操。
- 本次明确修正旧群房间设计中“状态只读该群上下文”的决定；用户已直接要求修复。

## 根因与行为

`spaceSnapshot` 按所选群过滤 sessions/runs，`spaceState` 据此计算状态。
私聊或另一个群中的运行被过滤后，当前群的 idle 会话使角色进入休闲动作。
真实 Bot 是同一身份，不能因为所看房间不同就忽略其工作。

- Bot 状态、状态筛选、执行计数和 3D 动作依据该 Bot 全部会话的真实投影。
  任一会话待处理则 attention，存在运行则 running，协作等待和 unknown 沿用现有模型。
- 详情中的当前执行也涵盖 Bot 的所有会话，保留每个 Run 的私聊/群来源，
  点击执行卡仍打开该 Run 的实际会话。增加范围说明，避免把外部工作说成当前群任务。
- 所选群的普通会话列表、历史、发送目标与主要“打开群聊”入口仍使用该群上下文。
  Agent/子 Agent 的群归属与上下文规则不变；公共区不重复摆放已有群的 Bot。
- 全部真实会话恢复空闲后，才重新允许休闲动作；新工作中断活动并沿原路回工位。
  不根据桌面图像、角色动作或文字猜测工作状态。
- 仅修改 BotHub 客户端；不改 DSH、DS Bot Host、监控协议或用户数据。

## 实施与验收

1. 统一 Bot 的状态/运行选择逻辑，接入房间、2D、详情和筛选。
2. 回归私聊执行＋群 idle、跨群执行、审批、协作等待、无群会话及完成回闲；
   保留消息/导航的上下文隔离测试；验证活动中断后不再做操。
3. 构建生成客户端，运行完整 BotHub 测试、check、lint 和 DS Bot 必需回归。
4. 用隔离 DSH + 仓库 mock 验证群房间展示私聊工具执行，更新截图和本地预览包/校验和。
   如使用合成动画时间，只用作单独诊断并明确记录，不能代替真实运行证据。
