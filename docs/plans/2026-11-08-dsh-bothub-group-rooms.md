# BotHub：一个群对应一个 3D 房间

用户明确要求按群组织 3D 空间。本切片落实总计划 5.1 的群空间映射，
将原来的单块工位平台改为有边界、群名和成员席位的房间。

## 行为

- 每个群对应一个房间，以 group ID 标识；同名群不合并，空群仍显示房间。
- 同一 Bot 在多个群中各有一个席位，但总人数仍按实体去重。
  房内只显示该 Bot 在本群的执行、等待状态和会话，不用私聊或其他群的活动染色。
- 私聊与普通 Agent 放在“公共区”。子 Agent 跟随明确的根会话归属，
  不因为父 Bot 加入多个群就复制到无关群。
- 点房间名或群筛选进入单房间；返回总览显示全部房间。
  点击成员打开该空间的详情；群成员优先打开本群，公共区打开私聊。
  从未产生隐藏群成员 Session 的成员也能打开群，后端重新检查成员关系。
- 群删除或成员移除后清除无效选中；未观测的执行保持未知。
  搜索和状态筛选作用于每个房内上下文；2D 的群筛选遵守相同语义。
- 保留只读观察与原生会话操作。进入房间不会修改群成员、创建 Session 或发消息。
- 3D 最多 24 个房间、50 个席位，超限明确提示，通过群筛选查看其他房间，
  2D 不截断成员。无 WebGL 仍回退 2D。房间布局是确定性的，无持续动画。

## 验证

单元测试覆盖多群同 Bot、群与私聊状态隔离、子 Agent 归属、空群、
重复群名、确定性布局、显示上限以及失效导航。
用隔离 mock 台架创建两个真实群，验证多房间、房间聚焦、成员详情、
群会话跳转、2D 与窄屏；录制单次连续演示。运行仓库规定的检查。

此前“配套安装包”修复按用户要求暂停，当前切片不安装到用户的 DSH。

## 实现与验收（2026-11-08）

已在 `feat/bothub-mvp` 工作区实现，基点为 `a50e2b9`，含未提交修改。
本轮没有新发布包，没有提交、推送或更新用户安装。此前安装诊断的工作区修改
保留，并随当前客户端重新构建；配套安装包任务仍暂停。

- `rooms.js`：按群构造席位、上下文筛选和确定性房间布局。
- `world.js`：独立地板与低墙、房间名称、总览／房间切换、按席位选中，
  保持按需绘制及共享资源释放。
- `view.js`：房内详情与 2D 群筛选使用同一上下文，群删除／成员移除后
  清除无效选中。团队统计继续按 Entity 去重。
- `monitor.js`：新增可选 `groupNavigation` 能力标记和带 groupId 的导航解析，
  在打开前确认群和成员关系；从未产生群成员 Session 时也能返回群聊 ID。
  对没有该能力的旧桥接，仅在已有可解析群会话时允许导航，避免误开私聊。
- 中英文 README 已同步。未增加持续动画、群编辑、模型调用或直接执行控制。
