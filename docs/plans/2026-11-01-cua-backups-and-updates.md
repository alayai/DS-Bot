# CUA 大容量备份和镜像更新

本轮落实用户选择的两个高优先级项目，保留当前 fork 分支和现有桌面。

- 备份默认上限 20 GiB，可在资源面板设置 1–1024 GiB；单文件上传仍为 200 MiB。
  Python 分块校验、复制和再次校验，最多 100000 个条目，manifest 最多 64 MiB。
  提交前保留完整性、身份、剩余空间检查，兼容已有 v1 备份。
- 备份、恢复和升级作为后台管理任务运行，提供阶段、字节进度及取消。
  页面关闭不取消任务；Host 中断由既有持久化操作日志恢复，不重放存储修改。
  取消不得发布未验证的新 home，恢复动作仅清理本任务的暂存卷。
- 镜像检查固定使用随包可信发行的 GitHub 仓库。只接受 evidence 分支提交：
  唯一父提交为对应发行源码，唯一修改为 runtime.lock.json，固定 archive 哈希，
  协议、平台、driver 与当前 runtime 兼容。不接受前端 URL 或任意镜像。
- 下载、完整性和兼容性检查在后台执行；下载不会切换现有桌面的镜像。
  验证后的镜像写入托管配置并加入 Broker 允许列表，重启仍可恢复。
  非托管 profile 保留手工管理，界面明确说明。
- 升级需要在停止桌面后再次确认，绑定当前 generation 和确切镜像。
  沿用备份、空桌面启动验证、home 迁移及启动验证；保留旧 home 与镜像配对回退。
- 验证包含大于 200 MiB 的真实容器备份往返、取消与隔离测试、发行证据异常、
  下载失败/重启持久化以及界面操作。Windows 桌面系统验收仍由用户执行。
