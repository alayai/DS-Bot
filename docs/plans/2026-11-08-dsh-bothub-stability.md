# BotHub：多窗口预览与持续运行验收

本轮承接桌面显示器需求，并补原计划 P4 的部分多窗口稳定性证据。

## 设计

- 同一浏览器存储分区、同一 `api/bot` 路径、同一 Bot 的被动 PNG 采集，使用 Web Locks 排队。
- 正常采集持有锁至少一秒，或直至截图完成；画面立即交给当前窗口，冷却期不延迟展示。不同 Bot 不互相阻塞。取消会立即结束冷却，因此窗口切换期间可出现短于一秒的间隔。
- 排队和在途截图复用现有取消/超时信号。页面隐藏、关闭、切换和卸载时取消；冷却等待可被立即中断。不会把图片、登录状态、控制票据写入锁、广播或持久化存储。
- 多个窗口分享采集时隙，各自仍通过已认证的预览通道读取。窗口越多，每个窗口的刷新越慢；现有五秒过期规则继续生效。
- 未提供 Web Locks 或存储策略禁用它时，退回已有单窗口限制。不同浏览器、不同 profile/存储分区以及原生 DS Bot 面板不参与协调；本轮不是服务端全局限流。
- 不新增宿主接口，不启动或接管桌面，不改变 idle 时间。真实容器及视频流另行验收。

## 验收计划

1. 单元测试：同 Bot 互斥和一秒间隔、不同 Bot 独立、排队/采集中/冷却中取消、拒绝后无重复调用、缺少能力的降级、长时间循环清理。
2. 实际浏览器与 Computer service + 测试 provider：至少三个窗口同时预览同一 Bot，记录服务端采集时间/峰值并发/每窗口新帧；关闭、隐藏、重载后检查锁与资源释放。
3. 隔离真实 DSH + mock 团队：多个 BotHub 页面持续运行，切换 2D/3D、开关预览、离线/恢复、刷新；检查连通性、错误、请求和卸载。此项不证明真实模型或真实桌面容器性能。
4. 两插件单元测试、生成检查和 lint；本轮不改 host，不重复宣称此前 51/52 smoke 已全绿。

当前 Docker daemon 不可连接，不能将测试 PNG 的结果记录为真实容器验收。
