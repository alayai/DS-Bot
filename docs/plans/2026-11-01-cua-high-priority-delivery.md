# CUA 高优先级交付

用户授权：完成首次系统安装、预构建镜像交付、资源管理面板。
在当前 fork 分支实现，不修改 DSH，不操作用户正在使用的容器或 DSH 数据。

## 首次安装和重启续接

- Windows Host 提供明确的系统安装确认。仅支持固定的 WSL 和容器引擎命令，
  不接受前端提供安装路径、脚本或参数。沿用用户管理接口，不暴露模型工具。
- 安装是持久后台任务，记录用户选择、阶段和系统启动标识。展示 UAC、安装器、
  需要重启、等待引擎启动、失败等状态；不替用户重启 Windows。
- 系统修改只在用户明确启动安装时执行；Host 重启后先只读检查环境，满足条件
  才接续已授权的镜像准备。不得因进程退出或返回结果丢失而自动重装系统组件。
- 初次安装能力归属 DSH Host，不能把访问 Web 页面误当作允许安装浏览器所在机器。

## 预构建镜像

- 保留现有 GHCR digest 交付和验收。实际发布必须来自已提交的配方并有真实 smoke。
- GitHub Releases 可作为无需 registry 登录的镜像分发通道：压缩 Docker archive
  以受控大小分片，manifest 记录各片 SHA-256、长度、image ID 和 recipe。
  可信发行 lock 固定 manifest 的 URL/哈希；下载逐片校验，再交给引擎 load，
  不在 Host 解压 tar。临时文件属于本任务，取消/失败清理。
- 发布工作流独立验证匿名下载，输出可审查的发行证据。只有实际成功才修改默认 lock。
  未发布、无权限、网络失败不算交付完成，不填写虚构地址。

## 资源管理

- UI 修改同一 Host 的运行桌面数、闲置停止时间、剩余空间/单 home 告警阈值。
  保存到 Computer registry，使用 revision 防旧窗口覆盖；读写权限沿用 Host。
- 降低并发上限不能强停现有桌面；超过目标时拒绝保存，要求用户先停桌面。
- 磁盘采样显示时间和失败状态，区分当前 home、引擎文件系统空间、配额范围。
  告警不声称能阻止另一个进程继续写盘。
- 硬配额必须由实际存储后端强制，不能用周期扫描模拟；只对验证支持的后端开放。
  现有普通 Docker named volume 不自动转换，不允许为了配额给 guest 特权。

## 验证

覆盖安装意图/重启/取消、缺工具/UAC 拒绝、旧 revision、持久设置与并发准入、
采样过期/失败、配额能力拒绝、发行分片完整性/取消/镜像替换。
执行单测、lint、生成文件校验、隔离 Bot smoke 和真实 guest 测试。
Windows 系统安装在 fixture 中验证命令和状态，不在用户工作机上执行安装或重启。

## 已实现的边界

- Windows 使用固定 WSL 命令和 winget 软件包 ID；缺少 Windows App Installer
  时显示处理说明，不在后台下载并执行未固定来源的安装器。安装确认归属当前
  DSH Host；取消停止 DSH 后续步骤，但可能无法撤销已经提权的独立系统安装器。
- 资源设置保存到 registry；采样间隔 60 秒，超过 120 秒显示过期。后台扫描
  不刷新闲置计时，失败保留同一代桌面的旧读数并标明失效，不跨绑定复用数据。
- 硬配额仅支持 Podman、rootful、XFS project quota。启用前创建独立的 64 MiB
  探针卷，申请 128 MiB 并要求内核返回 EDQUOT；失败拒绝保存，清理只认探针标签。
  配额随新 home 的创建、恢复和升级保留；既有 home 不原地转换。检查点副本和
  引擎根层不计入该 home 配额。Docker Desktop 普通卷没有这一能力，界面只提供
  告警；不能将此项宣称为 Windows Docker 的整盘硬配额。
- 镜像交付以实际发布工作流和匿名验证为准；没有通过时不改变默认发行 lock。
  Windows 真机安装验收和 Podman/XFS 实机配额验收仍须在对应环境进行。
