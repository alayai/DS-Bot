# BotHub 安装后无数据：配套交付与故障诊断

## 现场与原因

用户截图中 BotHub 界面正常加载，但成员为 0，提示连接中断。截图不足以确认
HTTP 状态或已安装 DS Bot 的版本，不能仅凭截图断言运行中的具体异常。

已确认交付缺陷：alpha.3 单独包没有包含 DS Bot 的 `botMonitor` 监控服务，
该服务只存在于工作区的 DS Bot 修改中；搭配原有已发布 DS Bot 安装时，
监控 API 返回 503。旧客户端把缺少服务、服务异常和网络失败统一显示为断线，
并把没有快照显示成 0 成员。这会让用户误以为安装成功却丢失了团队。

## 修复范围

- 保持现有公开服务和只读边界，不调用具有 bootstrap 副作用的 `api/bot state`
  作为回退，不读取用户 DSH 文件，也不修改 DSH。
- 缺少服务返回明确的 `bridge-missing`；服务异常仍为 `unavailable`。
  客户端仅接受已知错误码，认证/协议失败优先，绝不直接展示服务器错误正文。
- 缺少桥接显示配套更新 DS Bot 并重启宿主的指引；路由未加载、会话失效、
  网络断线分别提示。没有有效快照时统计显示“—”，不声称团队为空。
- 提供匹配的 BotHub 与 DS Bot 本地安装包、校验和和安装说明。
  兼容 DS Bot 包使用独立预发布版本，避免与 npm 同版本包混淆；
  只在打包暂存目录调整版本，不改 DS Bot 的发布版本。
- 使用包安装到隔离宿主验证，不再只以源码 link 台架作为安装成功的证据。
  保留历史产物，完成后停止测试服务。

## 验证要求

覆盖缺失桥接、未知错误正文、401/403、协议版本差异、路由缺失和会话失效。
覆盖缺失桥接期间旧快照清除，以及服务恢复后重新取数。
运行两个插件规定检查，并用实际打包产物启动隔离 mock 宿主，
确认 API 和 2D/3D 展示有真实成员。记录验证范围和未确认的现场条件。
